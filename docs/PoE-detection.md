# Определение PoE на порту в NetLynx

Этот документ описывает, **как бэкенд решает**, что на порту коммутатора есть активная выдача PoE (или близкий к этому признак), и **как веб-интерфейс** показывает индикатор ⚡. Цель — чтобы при смене кода было проще не потерять смысл каждого шага.

---

## Термины

| Термин | Смысл |
|--------|--------|
| **PSE** | Power Sourcing Equipment — коммутатор/инжектор, **отдаёт** питание по Ethernet. |
| **PD** | Powered Device — устройство, **потребляющее** PoE (камера, точка доступа и т.д.). |
| **ifIndex** | Числовой идентификатор интерфейса в SNMP; все источники PoE в итоге приводятся к нему. |
| **`poe_active` в БД** | Поле `device_interfaces.poe_active`: `true` / `false` / `NULL`. `NULL` означает «не удалось определить» или «в этом цикле не обновляли». |

---

## Общий порядок (один цикл опроса устройства)

1. SNMP: sysName / sysDescr.
2. IF-MIB: таблица портов.
3. **`WalkPoEDeliveringByIfIndex`** — SNMP PSE (RFC / Huawei / Cisco / Ubiquiti / SNR) → карта `ifIndex → true/false`.
4. Если в карте **нет** `true` и включён fallback — **SSH CLI** (`SSH_POE_*` из **env**, не SSH с карточки узла) для Ubiquiti/SNR.
5. Если карта всё ещё **пустая** — **LLDP-PD** last resort (без uplink на свитч).
6. **`ClearPoEOnFiberPorts`** — на SFP/оптике `poe_active=false` (серверная эвристика; UI дополнительно прячет ⚡ на fiber по каталогу портов).
7. Запись в БД: только явные ключи карты; иначе поле не трогается.

Реализация: `internal/poller/poller.go`, `internal/snmp/poe.go`, `internal/snmp/lldp_poe.go`, `internal/snmp/fiber_poe.go`, `internal/poecli/ubnt.go`.

**Важно:** SSH для PoE — только env `SSH_POE_USER` / `SSH_POE_PASS` / …; SSH учётные данные на карточке узла используются для бэкапа / config snapshot / port CLI, **не** для этого fallback.

---

## Шаг 3. SNMP: последовательность источников

Функция **`WalkPoEDeliveringByIfIndex`** объединяет несколько MIB. При **слиянии** в общую карту попадают в основном записи со значением **`true`** — так уменьшается риск массово записать «PoE выключен» там, где данные просто отсутствуют.

### 3.1. RFC 3621 — POWER-ETHERNET-MIB

- Стандартная таблица PSE-портов.
- По **`pethPsePortDetectionStatus`** и привязке к физическому интерфейсу определяется, что порт в состоянии **выдачи питания** (`deliveringPower` и эквиваленты в числовом виде).
- **Пояснение:** это «канонический» способ сказать «PSE сейчас кормит PD», если агент SNMP реализует ветку `1.3.6.1.2.1.105`.

### 3.2. Huawei — HUAWEI-POE-MIB

- Свои OID на потребление/класс PD по порту.
- **Пояснение:** на части коммутаторов Huawei стандартная ветка RFC не заполнена, зато отвечает вендорская.

### 3.3. Cisco — CISCO-POWER-ETHERNET-EXT-MIB

- Признак обнаруженного устройства на PSE-порту.
- **Пояснение:** дополняет картину там, где Cisco отдаёт расширенный MIB, а не только RFC.

### 3.4. Ubiquiti / Broadcom fastPath — `1.3.6.1.4.1.4413.1.1.15`

- Мощность и ток на порту (как правило в мВт и мА).
- **Пояснение:** на части прошивок EdgeSwitch **эта ветка отсутствует** — тогда этот шаг ничего не даёт, и полезны fallback-и ниже.

### 3.5. Условие перехода к LLDP

- Если после шагов **3.1–3.4** (и SNR) в карте **есть хотя бы один ключ** (в том числе `false`), **LLDP в этом SNMP-шаге не вызывается**.
- LLDP-PD вызывается в **поллере позже**, только если карта по-прежнему **пустая/nil** (MIB молчат) **и** SSH-fallback не вернул таблицу портов.

**Пояснение:** «сосед объявил себя PD» не равно «PSE сейчас кормит». Если SSH отработал, его `true`/`false` важнее LLDP.

### 3.6. Запасной путь — LLDP-EXT-DOT3-MIB

- Обход OID **`lldpXdot3RemPowerPortClass`** (в т.ч. legacy).
- Если сосед заявляет класс **PD**, локальный порт сопоставляется с **`ifIndex`**.
- Пишется в `poe_active` **только как last resort**, когда нет данных PSE и нет SSH-таблицы. На EdgeSwitch без 4413 и без SSH это сохраняет прежнюю индикацию.
- **Фильтр uplink:** если LLDP-сосед похож на другой коммутатор (имя `Eltex`, `EdgeSwitch`, … или удалённый порт `gi1/0/23`, `te`, `lag` и т.п.), для этого `ifIndex` пишется **`false`**, а не `true` — чтобы uplink на свитч не показывал ⚡.

### 3.7. Пустой результат и ошибки SNMP

- Если **ни один** источник не пометил порты, а часть обходов завершилась ошибками, функция может вернуть **пустую или «нулевую» карту** без массового `false`.
- **Пояснение:** так поллер **не затирает** `poe_active` ложными «нет PoE» на устройствах без PoE-MIB (типичный случай EdgeSwitch).

## Шаг 4. SSH CLI fallback (опционально)

Включается **только если** одновременно:

- в конфигурации включён флаг SSH PoE fallback;
- задан пользователь SSH;
- после SNMP **нет ни одного** `ifIndex` с **`true`**;
- в **sysDescr** есть признаки **Ubiquiti / EdgeSwitch** или **SNR**.

SSH пишет и **`false`** по разобранным строкам CLI — чтобы снять залипшую молнию, когда камеру сняли.

Дальше:

1. По **sysDescr** выбирается **профиль вендора** (команда привилегированного режима: `en`, `enable` и т.д., набор команд `show poe …`).
2. Для Ubiquiti EdgeSwitch обычно нужен **второй пароль** (enable); задаётся отдельной переменной окружения, с откатом к основному паролю SSH, если enable-пароль не задан.
3. Выполняется интерактивная сессия **в одном SSH-канале** (чтобы избежать ошибок открытия второго канала после выхода из привилегированного режима).
4. Вывод команд (например **`show poe status all`**) парсится: строки с именем порта (`0/3` и т.п.) сопоставляются с **`ifIndex`** через ту же таблицу интерфейсов, что и SNMP. Активность определяется по **Detection** и числовым колонкам (потребление, напряжение, ток).
5. Если SSH закрывает сессию **без exit-status**, но **текст вывода уже есть**, это **не считается фатальной ошибкой** — парсер всё равно обрабатывает вывод (особенность части прошивок).

Переменные окружения (см. `.env.example`): `SSH_POE_FALLBACK_ENABLED`, `SSH_POE_USER`, `SSH_POE_PASS`, `SSH_POE_ENABLE_PASS`, `SSH_POE_KNOWN_HOSTS` (по умолчанию `/var/lib/netlynx/ssh_known_hosts`), порт, таймаут.

Ошибки fallback логируются уровнем **WARN**, чтобы их было видно в `journalctl`.

После смены прошивки на **коммутаторах** ключи SSH могут измениться (`knownhosts: key mismatch`). Один скрипт по **онлайн**-свитчам (`device_category=switch`, `last_snmp_ok` или `online_override=true`; оффлайн не опрашиваются): сначала современные алгоритмы, если handshake не вышел — переходные, затем legacy (Eltex OpenSSH 5.x). Порт из `devices.ssh_port` или 22:

```bash
sudo /usr/local/sbin/refresh-ssh-known-hosts.sh
# или один свитч: sudo HOSTS=10.0.0.1 /usr/local/sbin/refresh-ssh-known-hosts.sh
```

Лог скрипта — куда направите stdout/stderr при запуске (например `tee`); отдельный путь `/tmp/invetor-refresh-keys.log` скриптом **не** создаётся автоматически. Старый known_hosts сохраняется как `ssh_known_hosts.bak.*`.

## Шаг 5. Запись в базу данных

Для каждого порта при upsert интерфейса:

- если итоговая карта PoE **не `nil`** и для данного `ifIndex` есть ключ — в БД пишется **`poe_active` = значение** (`true` или `false`);
- если ключа **нет** или весь обход PoE вернул **`nil`** (MIB молчат) — поле **не трогается** (`COALESCE` сохраняет старое / `NULL`).

Явный `false` пишется, когда источник **перечислил порт** (RFC detection ≠ delivering, 0 мВт, SSH «не delivering»). Так молния гаснет после снятия PD, но **не** стирается из‑за таймаута всего PoE-walk.

## Веб-интерфейс: когда показывается ⚡

1. Не fiber-порт (каталог моделей + эвристика имени) — иначе молнии нет.
2. Если **`poe_active === true`** — ⚡.
3. Иначе если **`poe_power_w > 0`** — ⚡.
4. Иначе нет.

Серверный сброс PoE на SFP (`ClearPoEOnFiberPorts`) и UI-каталог портов могут чуть расходиться по эвристике имени — см. [Port-Model-Catalog.md](Port-Model-Catalog.md).

## Краткая блок-схема

```text
SNMP опрос → IF-MIB
         → PoE MIB (RFC / Huawei / Cisco / 4413 / SNR)
         → если нет true + SSH_POE_* env → SSH show poe
         → если карта пустая → LLDP DOT3 PD (last resort)
         → ClearPoEOnFiberPorts (SFP)
         → запись явных ключей в БД

UI: не fiber AND (poe_active || poe_power_w > 0)
```

## Диагностика: RFC 3621 (105) и EdgeSwitch

Ответ **No Such Object** на `1.3.6.1.2.1.105` нормален: **RFC 3621** на агенте часто не реализован. Далее NetLynx пробует **Huawei**, **Cisco**, **Ubiquiti EdgeSwitch** (Broadcom **fastPath** `1.3.6.1.4.1.4413.1.1.15`). Проверка вручную для EdgeSwitch:

```bash
snmpwalk -v2c -c public HOST 1.3.6.1.4.1.4413.1.1.15.1.1.1
```

**EdgeSwitch *-lite* (пример: ES-16-150W, 1.9.3-lite):** в MIB **EdgeSwitch-POWER-ETHERNET-MIB** заявлены `agentPethOutputPower` / `agentPethOutputCurrent`, но агент на части сборок отвечает **No Such Object** на всю ветку **1.1.15** — тогда **`poe_active` по SNMP не заполняется** (остаётся `NULL`).

**EdgeSwitch без `105` и без `4413.1.1.15`:** поллер пробует **LLDP-EXT-DOT3** — `lldpXdot3RemPowerPortClass`, значение **2** = PD. Нужны **LLDP** и TLV мощности от соседа.

**SSH fallback:** если после SNMP карта без `true`, поллер пробует CLI по **env** `SSH_POE_*` (до LLDP-PD). LLDP — только last resort, если MIB и SSH ничего не дали.
