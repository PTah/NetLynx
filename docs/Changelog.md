# Журнал версий NetLynx

Полная история изменений. В [README](../README.md) — последние версии и правила нумерации.

**0.4.8** — документация: журнал версий вынесен в журнал версий вынесен в `docs/Changelog.md` (в README — последние релизы) (в README — последние релизы), добавлен чек-лист **«Первый запуск после установки»**, новый [VLAN.md](VLAN.md) (база VLAN, access/trunk/native/allowed, проверка последствий удаления, ограничения) и полный английский [README.en.md](../README.en.md).

**0.4.7** — документация для админов: в README добавлены разделы **«Что умеет»**, **«Настройки окружения (env)»**, **«Обновление и эксплуатация»** и оглавление; новый [docs/Notifications.md](Notifications.md) — Telegram/email/webhook, фильтры, полный список типов событий, статистика и чеклист «почему не приходит»; исправлены битые ссылки в `desktop/README.md`.

**0.4.6** — Статистика уведомлений: периоды от **1 часа** до **365 дней** (1–12/24/48/72 ч, 7…365 дн.); API принимает `hours` (до 8760).

**0.4.5** — Настройки → Уведомления → **Статистика**: таблица по устройствам за период — сколько раз уходили в оффлайн (`DEVICE_OFFLINE`/`DEVICE_ONLINE`) или сколько раз у ИБП пропадало питание (`UPS_ON_BATTERY`/`UPS_MAINS_OK`); API `GET /api/v1/settings/notifications/stats`.

**0.4.4** — журнал: повторные SNMP-сбои одного эпизода (узлы без агента) пишутся в debug, warn остаётся только на первом сбое; FDB-попытка отмечается и при ошибке, поэтому «bridge port map empty» теперь не чаще раза в `FDB_POLL_INTERVAL_SECONDS` на узел (было каждые 5 минут).

**0.4.3** — интервал тяжёлого опроса можно задать в карточке узла («Тяжёлый опрос (с)», `PATCH /devices/{id}/monitoring`, в БД `NULL` = `POLL_HEAVY_SECONDS`). Неудачный опрос FDB теперь тоже отмечается (`last_fdb_poll_at`), поэтому узлы без bridge-MIB не пробуются каждые 5 минут и не засоряют журнал `bridge port map empty`.

**0.4.2** — util/rate пишутся в историю не чаще `METRICS_UTIL_INTERVAL_SECONDS` (по умолчанию 60 с): после перехода на 15-секундный лёгкий опрос в `metric_samples` уходило ~19 млн строк/сутки, с троттлингом — ~10 млн (уровень до перехода, ~1 семпл на порт в минуту). Статусы портов, LINK_UP/DOWN и flap-детект по-прежнему работают каждые 15–20 с.

**0.4.1** — SNMP-backoff для узлов без SNMP-агента (камеры, ПК, ТВ): после 3 сбоев подряд SNMP не опрашивается 15 минут, ICMP продолжает работать — меньше таймаутов в журнале, слоты опроса не простаивают (было ~70 неудачных SNMP-опросов в минуту).

**0.4.0** — лёгкий и тяжёлый опрос разделены: критичные типы (роутер, коммутатор, сервер) опрашиваются не реже **15 с** (`POLL_CRITICAL_INTERVAL_SECONDS`), остальные — по своему интервалу; тяжёлые таблицы (LLDP/CDP/ARP/PoE/STP/chassis/FDB, роли портов) — раз в `POLL_HEAVY_SECONDS` (300 с по умолчанию) вместо каждого опроса. Очередь: сначала критичные типы, внутри — самые просроченные. PoE-флаги и роли портов на лёгком опросе не перезаписываются. Ожидаемый эффект: падение коммутатора видно в пределах ~15–30 с, нагрузка на сеть и коммутаторы ниже.

**0.3.1** — пропажу узлов из сети NetLynx больше не проспит: `DEVICE_OFFLINE` пишется **сразу** на первом опросе, если узел, который раньше отвечал на ICMP, перестал отвечать и по ICMP, и по SNMP (правило «2 подряд» осталось только для SNMP-блипа при живом ping). Очередь опроса: сначала самые просроченные узлы, до 40 параллельно, мёртвый узел проверяется короткой SNMP-пробой (2 с без повторов) вместо 10 с — слепое окно сократилось с минут до периода опроса. Причина случая: EdgeSwitch 24 #5 (10.0.0.1) перезагружался по прошивке между двумя опросами (02:31:58 → 02:36:24) — не опрашивался в момент ребута, поэтому оффлайн не был зафиксирован.

**0.3.0** — режим «Авто (Ping)» доведён до конца: узел опрашивается только ICMP, время опроса (`last_poll_at`) обновляется корректно (иначе интервал игнорировался), SNMP-поля остаются пустыми — никаких таймаутов и ложных «ошибок SNMP» у телефонов/IoT.

**0.2.9** — режим достижимости **Авто (Ping)** больше не опрашивает SNMP: после ICMP-проверки опрос завершается, залипшие `last_snmp_ok`/`last_snmp_error` у таких узлов сбрасываются.

**0.2.8** — ИБП: предупреждения по заряду АКБ (`UPS_CHARGE_LOW` / `UPS_CHARGE_CRITICAL` / `UPS_CHARGE_DROP`), быстрый разряд (`UPS_DISCHARGE_FAST`, %/мин), малая автономия (`UPS_RUNTIME_LOW`) и «питание не вернулось» (`UPS_ON_BATTERY_LONG`, >10 мин на батарее); тревоги карт ИБП по SNMP-трапам видны в логах трапов — [docs/UPS.md](UPS.md).

**0.2.7** — ИБП: строковые поля UPS-MIB (`manufacturer`, `model`, `ident_name`) читаются корректно — карты EPPC/APC NMC отдают OctetString как `[]byte`, из-за чего модель и производитель не попадали в снимок.

**0.2.6** — ИБП по SNMP (UPS-MIB, RFC 1628): тип узла «ИБП», снимок статуса (заряд, автономия, вход/выход, нагрузка, температура, аварии), история метрик до года, события `UPS_ON_BATTERY` / `UPS_MAINS_OK` / `UPS_BATTERY_LOW` / … — [docs/UPS.md](UPS.md).

**0.2.5** — Настройки порта: Trunk + Native VLAN + Allowed VLAN (`mode trunk` / `native` / `allowed`); на вкладке VLAN — Native и режим set для абсолютного списка.

**0.2.4** — Порты: после выкл/вкл и смены PoE модалка больше не показывает ложный PoE+ из устаревшего snapshot (нельзя было включить PoE через UI, хотя на свитче он был off).

**0.2.3** — МФУ: история тонера/страниц в БД до года (`METRICS_PRINTER_RETENTION_DAYS`); на карточке узла выбор периода 1…365 дн. и сводка расхода.

**0.2.2** — МФУ: на дашборде при фильтре «МФУ» колонки страниц/тонера вместо CPU; CPU для МФУ сбрасывается; оповещения `TONER_LOW` (≤5%) и `TONER_CRITICAL` (≤2%) + мигание строки при ≤2%.

**0.2.1** — Узлы: при фильтре только «Роутеры» в таблице «Список» колонка **CPU** (загрузка из SNMP) сразу после «SNMP / ping».

**0.2.0** — Сброс нумерации версий: текущий релиз **0.2.0** (ранее линия `0.13.x`). Дальше: `0.2.1`…`0.2.9` → `0.3.0`…`0.3.9` → `0.4.0`… (см. [нумерацию](../README.md#нумерация-версий-с-020)). Состав: всё из `0.13.6`, включая снимки RouterOS для MikroTik AP (wAP).

**0.6.0**

- Веб: сетка портов на карточке узла (цвет по скорости линка), подписи вида `0/1` для стека, легенда; колонка и молния **PoE** — по **SNMP POWER-ETHERNET-MIB** (выдача питания) и запасная эвристика по тексту порта.
- Веб: скорость в таблице портов **≥ 1 Гбит/с** показывается в **Гбит/с** (например 1 Гбит/с, 10 Гбит/с), ниже — в Мбит/с.
- Веб: у всех основных таблиц — **перетаскивание ширины колонок** с сохранением в `localStorage`; на странице **Узлы** строки с **ошибкой SNMP** (`last_snmp_ok=false`) визуально приглушены.
- Веб: favicon (буквы **IM**), SVG + PNG.
- Бэкенд: миграция **`013_poe_active.sql`** — поле `device_interfaces.poe_active`; при недоступности MIB значение не затирается (остаётся `NULL` до успешного опроса).
