# VLAN: база, порты (access / trunk / native / allowed)

NetLynx умеет читать и менять VLAN-конфигурацию коммутатора **по SSH** (CLI), а не по SNMP. Всё, что вы видите на вкладке VLAN и в колонке VLAN таблицы портов, взято из `show run` (снимок) и текущего опроса портов.

Где это в интерфейсе: **Узлы → карточка узла → вкладка «VLAN»** и **та же карточка → «Порты»** (колонки VLAN / режим / allowed).

## Что нужно, чтобы работало

| Требование | Где задать |
|---|---|
| SSH-доступ к коммутатору | карточка узла → поля `ssh_user` / `ssh_password` / `ssh_port` (+ `enable password`, если нужен) |
| Вендор известен | поле `ssh_vendor`: `auto` (определение по `sysDescr`) либо явно — `ubiquiti`, `eltex`, `snr`, `mikrotik`, `cisco`, `aruba`, `zyxel`, `huawei`, `hp`, `tplink`, `dlink`, `dahua`, `hikvision`, `hiwatch` |
| Учётка с правом записи | `read-only` пользователь покажет VLAN, но не даст изменить |
| Снимок конфигурации | «Сохранить конфиг» в карточке (или плановая синхронизация) — база VLAN берётся из конфига |

Если SSH не настроен — вкладка покажет данные из последнего снимка конфигурации, а изменения будут недоступны с понятной ошибкой.

## VLAN database

Таблица VLAN устройства: `id`, имя, где используется.

- **Создать** VLAN — `POST /api/v1/devices/{id}/vlans` (`vlan_id`, `name`). VLAN создаётся в конфигурации коммутатора (`vlan <id>` + `name`).
- **Переименовать** — `PATCH /api/v1/devices/{id}/vlans/{vlanId}`.
- **Удалить** — `DELETE /api/v1/devices/{id}/vlans/{vlanId}` (или списком: `DELETE /api/v1/devices/{id}/vlans` с `vlan_ids`).

**Важно:** назначить порту VLAN, которого нет в базе устройства, нельзя — API вернёт ошибку. Сначала создайте VLAN, затем вешайте на порт.

### Удаление: проверка последствий

Перед удалением UI запрашивает `GET /api/v1/devices/{id}/vlans/delete-impact?vlan_ids=10,20` и показывает:

- есть ли VLAN в базе устройства,
- используется ли он **на портах** (в какой роли),
- встречается ли в конфиге.

Удаление используемой VLAN — это разрыв связности: NetLynx покажет предупреждение, но решение за вами (blade-логика: одна VLAN на многих портах = широкий радиус).

## Порты: режимы и VLAN

Колонка **VLAN** в таблице портов и редактор порта работают по одной модели:

| Режим | Что означает | Как применяется |
|---|---|---|
| **Access** | порт в одной VLAN, трафик нетегированный | `access vlan <id>` (на Ubiquiti/EdgeSwitch — `switchport` + `vlan`), режим untagged |
| **Trunk** | тегированный транк + одна **native** VLAN | тегированные VLAN + `native vlan <id>` |
| **No VLAN** | порт без VLAN (например, транк без native или «голый» аплинк) | VLAN снимается |

Дополнительно:

- **Native VLAN** — отдельное поле для транка (что уходит нетегированным).
- **Allowed VLAN** — список разрешённых VLAN на транке; режимы: `add` (добавить), `remove` (убрать), `set` (задать ровно этот список), `all` (разрешить все).
- Изменение порта: `PATCH /api/v1/devices/{id}/ports/{ifIndex}/vlan` (`mode`, `access_vlan`, `native_vlan`, `allowed_mode`, `allowed_vlans`).

После применения NetLynx возвращает, что именно сделал (`via`: tagged/untagged) — это видно в уведомлении в UI.

Если на порту висит PoE-устройство, порт не выключается: VLAN применяется «на лету» (сброс PoE — отдельная кнопка).

## Смежные вещи

- **VLAN на топологии.** LLDP/CDP о VLAN не знают: если связь идёт через SFP или VLAN-разрез, задайте линк вручную — [Manual-Topology-Links.md](Manual-Topology-Links.md).
- **VLAN при смене адреса/склада.** Смена IP и «склад» описаны в карточке узла; при переносе устройства VLAN на портах не меняется автоматически.
- **История изменений VLAN.** Каждое изменение порта/базы VLAN — это событие в журнале и новый снимок конфигурации: [Config-History.md](Config-History.md).
- **Игнор-лист портов.** Если порт нужно исключить из событий (например, тестовый стенд) — [Ignore-List.md](Ignore-List.md).

## Ограничения

- Запись возможна только по SSH; по SNMP VLAN не меняются (Q-BRIDGE читается для FDB, но не для записи).
- Синтаксис команд зависит от вендора и прошивки: если вендор определён неверно, поставьте `ssh_vendor` вручную.
- VLAN 1 — особый случай: на большинстве вендоров её нельзя удалить/переименовать, «No VLAN» ≠ «VLAN 1».
- Если SSH-сессия занята (кто-то в терминале), коммутатор может отказать — повторите операцию.
- Массовые изменения применяются последовательно; при ошибке на одном порте остальные всё равно применяются, ошибка возвращается в ответе.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/devices/{id}/vlans` | VLAN-база узла (источник: `config`/`snmp`) |
| POST | `/api/v1/devices/{id}/vlans` | создать VLAN |
| PATCH | `/api/v1/devices/{id}/vlans/{vlanId}` | переименовать |
| DELETE | `/api/v1/devices/{id}/vlans/{vlanId}` | удалить VLAN |
| DELETE | `/api/v1/devices/{id}/vlans` | удалить список (`vlan_ids`) |
| GET | `/api/v1/devices/{id}/vlans/delete-impact` | предупреждение перед удалением |
| PATCH | `/api/v1/devices/{id}/ports/{ifIndex}/vlan` | режим порта + VLAN |

Полный список — [API.md](API.md).
