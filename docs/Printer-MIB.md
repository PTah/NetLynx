# Printer-MIB: страницы и тонер (МФУ / принтеры)

Kyocera и Sharp (и большинство сетевых МФУ) отдают данные по **IETF Printer-MIB, RFC 3805** (`1.3.6.1.2.1.43`). Фирменные ветки (Kyocera `1347`, Sharp `2385`) — только fallback, если стандарт молчит.

NetLynx опрашивает Printer-MIB у узлов с типом **МФУ** (`mfu`; алиасы `принтер` / `printer`) и если `sysDescr` похож на печатную технику.

## Страниц всего

Основной OID: **`1.3.6.1.2.1.43.10.2.1.4`** (`prtMarkerLifeCount`).  
Типичный экземпляр: `1.3.6.1.2.1.43.10.2.1.4.1.1`. Берётся максимальное неотрицательное значение по walk (несколько маркеров).

## Остаток тонера

Таблица **`prtMarkerSuppliesTable`** (`1.3.6.1.2.1.43.11.1`):

| Поле | OID |
|------|-----|
| Colorant index | `…43.11.1.1.3` |
| Type | `…43.11.1.1.5` (3 = toner, 21 = tonerCartridge; 4 = waste — пропускаем) |
| Description | `…43.11.1.1.6` |
| Unit | `…43.11.1.1.7` (`18` = percent по RFC 3805) |
| Max | `…43.11.1.1.8` |
| Current | `…43.11.1.1.9` |

Цвет **не зашит индексами 1–4**. Сначала `prtMarkerColorantValue` (`1.3.6.1.2.1.43.12.1.1.4`), иначе подстроки Black/Cyan/Magenta/Yellow в description. Порядок CMYK на железе разный (иногда waste на индексе 1).

### Процент

- Unit = percent → берём current (если max ≠ 100 — `current/max*100`).
- Иначе **`% = current / max * 100`**.
- Current **−2** — неизвестно; **−3** — «есть остаток», точного числа нет.

Kyocera, если IETF не дал процент: `1.3.6.1.4.1.1347.40.10.1.1.3.{1–4}` (уже 0–100).

## UI

- **Узлы → Список:** колонки «Страниц всего» и «Остаток тонера» только когда в фильтре типов включены **исключительно МФУ**. Цветное МФУ — все картриджи.
- **Карточка узла:** рядом с CPU кликабельные страницы и тонер → график 24 ч (`metric_samples`: `page_count`, `toner_black_pct` / `_cyan_` / `_magenta_` / `_yellow_`).
